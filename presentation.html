Project Context

The Hack Day Challenge

TicTime is built with vanilla HTML, CSS & JavaScript. Our mission was to solve 3 critical issues without adding heavy frameworks.

📦 Problem #20

No Offline & No Install

  • Issue: The game stopped working when offline and lacked web app metadata.
  • Goal: Transform into an installable PWA with full offline capabilities.

♿ Problem #19

Inaccessible to Users (Hard)

  • Issue: Non-interactive <div> cells; no keyboard navigation; silent on screen readers.
  • Goal: Implement W3C ARIA Grid and spoken live announcements.

🧪 Problem #18

Zero Tests & Hidden Bugs

  • Issue: Broken anti-diagonal [2,4,7] and 9th-move wins wrongly called draws.
  • Goal: Build native unit test suite and automated GitHub Actions CI.
Problem #20

Offline Capability & PWA Installation

Enabled zero-internet gameplay and standalone desktop/mobile installation.

🛠️ Core Architecture Changes

  • Web App Manifest (manifest.json): Standalone display mode, brand theme color #7c3aed, and responsive 192px/512px icons.
  • Service Worker (sw.js): Pre-caches application shell with Stale-While-Revalidate caching strategy and offline navigation fallback.
  • In-App Installer (index.html): Added interactive 📲 Install App button in the header.
  • Adaptive Cross-Platform Engine (js/main.js): Native prompt for Chrome/Edge/Android; tailored Dock/Home Screen walkthrough for Safari macOS & iOS.

Problem #19 · Hard

Keyboard & Screen Reader Accessibility

Engineered full WCAG compliance and W3C WAI-ARIA Grid navigation.

⌨️ Universal Access Features

  • Semantic Button Grid: Converted static <div> cells into native <button type="button" class="cell" role="gridcell">.
  • W3C Roving Tabindex: Keyboard users press Tab once into the board, navigate via Arrow Keys (← → ↑ ↓ Home End), and Tab once to exit.
  • Natural & Coordinate Labels: Every cell dynamically announces e.g. Top Left (Row 1, Column 1), empty or ... marked X.
  • Spoken Live Announcements (aria-live): Verbal screen-reader updates on turns, moves, wins, and draws.
  • Visible Focus Rings: High-contrast neon focus outlines on .cell:focus-visible.

📂 Files Changed & Highlights

  • index.html: Added role="grid", aria-live="polite" on status, and dedicated #sr-announcements live region.
  • js/ui.js: Button generation, coordinate system, roving tabindex, arrow navigation handler.
  • js/main.js: Verbal announcement triggers; guarded against double-marking; auto-focused cell 0 on reset.
  • css/styles.css: Button styling reset, focus rings, .sr-only utility.

Problem #18

Automated Tests & CI/CD Workflow

Zero-dependency automated test suite using Node.js's native test runner with GitHub Actions.

🐛 Bugs Caught & Fixed

  • Bug 1 (Broken Anti-Diagonal): In js/game.js line 6, secondary diagonal was incorrectly indexed as [2, 4, 7]. Corrected to [2, 4, 6].
  • Bug 2 (9th-Move Draw Bug): In getGameResult(), the game checked for full boards before win lines. If a player won on the 9th move, it declared a draw. Prioritized win checking over draw checking.
  • Universal Export: Added module.exports so rules run both in the browser and in Node.js test environments.

🧪 Automated Test Suite

  • Native Node Test Runner (node:test): Zero npm installs or external dependencies.
  • 13 Unit Tests Passing:
    ✔ createEmptyBoard (9 null cells)
    ✔ nextPlayer (X ↔ O transitions)
    ✔ WIN_LINES (all 8 valid combinations)
    ✔ getGameResult (rows, columns, diagonals, draws, 9th-move wins)
  • GitHub Actions CI (.github/workflows/test.yml): Runs automatically on every push & PR.
